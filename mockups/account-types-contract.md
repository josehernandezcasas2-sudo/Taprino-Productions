## The website (one builder) — files under `pages/`, `components/`, `styles/globals.css`

1. **`/start`** (`pages/start.js`, new): the Main board. No site header, no tab bar (draw the `.welcome-bar` brand strip like `/welcome`, with Skip at the right). Server: signed out → redirect `/account`; `readAccountTypes(userId)`; when `!askDue({ signedIn: true, state })` redirect straight to `next` (through `safeNext` from `lib/privateBetaRules.js`; default `/`); props: `next`, the starting selection = `suggestedTypesFor` (ordered, the first is the main), `isCreator`. `noindex`, `private, no-store`. UI: `TYPE_WORDS.askTitle`, `askIntro`, the four cards from `askCards(state)` as toggle buttons (`aria-pressed`, icon tile, label, blurb, tick box, the `TYPE_WORDS.mainChip` pill on the main); when two or more are ticked, a small "Main" row of chips (radiogroup, `makeMain`) under the cards so the main can be changed without unticking; `askSkipNote`; the orange button `continueLabel(...)` (disabled while nothing is ticked) → `POST /api/account/types { types, main }` → `router.replace(next)`; `TYPE_WORDS.skipLong` link and the bar's Skip → `POST { skip: true }` → `router.replace(next)`. A 503 `migration-126` goes on to `next` silently; any other failure shows `TYPE_WORDS.failed` and stays. 16px fields rule doesn't apply (no fields); buttons ≥ 44px. Phone first; on a laptop the same column centred (max 520px).
2. **Every way into a brand-new account asks**: `pages/account.js` (the sign-in card's `signUpForceRedirectUrl` and the Create account button's `forceRedirectUrl`) → `/signed-in?next=/account`; `pages/welcome.js` (the invitation's `<SignUp>` and the sign-in box's `signUpForceRedirectUrl`) → `/signed-in?next=<next>`. Mid-task sign-ups (`stayHereSignUpProps`) stay as they are: they must return to the page.
3. **The account hub's nudge** (`pages/account.js`, signed in): when `askDue` (read the state on the server with `readAccountTypes`), a small card above the tiles: `TYPE_WORDS.askTitle`, a one-line `TYPE_WORDS.askSkipNote`, "Pick" → `/start?next=/account` and `TYPE_WORDS.skip` → `POST { skip: true }` then hide the card.
4. **Account → Profile** (`components/account/ProfileSection.js` / `pages/account/profile.js`): a "Your types" card at the top of the public form with `id="types"`: `typesRow(state)` (label, value, the Change button; greyed with `note` before 126). Change opens the **Your types sheet** (the Switch board): a bottom sheet under 900px, a dialog from 900px (follow the look of the messages sheets / `.ebx` boxes; focus to the title, Escape and × close, focus back to Change, `keepScrollInside` from `lib/menuScroll.js` so the page behind never moves). Rows from `sheetRows(state, { isCreator })`: a checkbox per type (label + line), the MAIN pill or a "Make main" button (`canMakeMain`), the creator note with its `/apply` link; `TYPE_WORDS.sheetNote`; Save (`saving` while sending) → `POST /api/account/types` → close, update the row, and tell the rest of the page and the ☰ menu (dispatch the same kind of window event the avatar save already uses for the tab bar, or add one: `tapa:account-types`). The sheet saves on its own, never as part of the profile's Save. Opening `/account/profile#types` opens the sheet once the page has loaded.
5. **The ☰ menu's you card** (`components/SiteMenu.js`): under the name, `menuTypes(state)` from `lib/accountTypeRules.js` (call it in the component; `lib/siteMenuRules.js` stays import-free and unchanged): the `line` (when not empty) in the plan line's style; when `chips` exist, the label `Your main` and the chips as a radiogroup (the main filled gold, others outlined) — choosing one posts `{ types, main }` and updates the card at once (optimistic, rolled back with `TYPE_WORDS.failed` on an error); the `note`; and `add` as a dashed "+ Add a type" chip linking to `/account/profile#types` (closing the menu). The state comes from `/api/my-role`'s `accountTypes` (wherever the menu already gets the role and name) and is updated by `tapa:account-types`. Signed out or `accountTypes: null`: none of it.
6. **The public profile** (`pages/profile/[userId].js`): `typesLine(types, main)` under the name row (e.g. "Crew · also Cast"), nothing for a watcher. The sections — both the jump list and the sections themselves, **in DOM order, not CSS order** — follow `mainFirst(items, main, keyOf)` with the keys: `profile-about` → `about`, `profile-crew` → `card`, `profile-record` → `record`, `profile-locations` → `places`, `profile-latest` and `profile-posts` → `posts`, `profile-tagged` → `work`, `profile-pitches` → `pitches`; `profile-saved` / `profile-backed` keep their place among the rest.
