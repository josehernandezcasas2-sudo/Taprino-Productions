# Account types, phase 1 — the website, as built (2026-11-18)

The website half of `mockups/account-types-contract.md` ("The website", items 1–7). No money, no badges, no plan names. Nothing under `mobile/` was touched; the files the contract marked as already written (`lib/accountTypeRules.js`, `lib/accountTypes.js`, `pages/api/account/types.js`, `pages/api/my-role.js`, `pages/signed-in.js`, `lib/profileHub.js`, the migration) were not changed.

## File by file

- **`pages/start.js`** (new) — the Main board. `getServerSideProps`: `private, no-cache, no-store`; `next` through the door's `safeNext` (default `/`); signed out → 307 `/account`; `readAccountTypes(userId)`; when `!askDue` → 307 straight to `next`; props `next`, `suggested` (`suggestedTypesFor`, the first is the main), `isCreator`. No site header, no tab bar: the `.welcome` / `.welcome-bar` brand strip with **Skip** at its right. The title, intro, the four cards from `askCards` as toggle buttons (`aria-pressed`, icon tile, label + the `MAIN` pill on the main, blurb, tick box), the **Main** chips (a radiogroup, `makeMain`, arrow keys move and choose like radio buttons) when two or more are ticked, `askSkipNote`, the orange `continueLabel(…)` button (disabled with "Pick one, or skip" while nothing is ticked; "Saving…" while sending), the `skipLong` button. Continue → `POST { types, main }`, Skip (either) → `POST { skip: true }`, then `router.replace(next)`; a 503 `migration-126` goes on to `next` silently, anything else shows `TYPE_WORDS.failed` and stays. `noindex` is the page's own meta tag — an `X-Robots-Tag` set in the page replaced the middleware's (`noai, noimageai`), so it isn't set there. Phone first; the column is 520px at most, centred; the foot (button + skip) sticks to the bottom so it stays on screen at 320×568.
- **`components/account/AccountTypeBits.js`** (new) — what the pieces share: `ACCOUNT_TYPES_EVENT` (`tapa:account-types`) and `announceAccountTypes(state)`; `postAccountTypes(body)` (→ `{ ok, state }` or `{ ok: false, status, code, error }`); the four type icons and their tints (from the Main board); `TickIcon`, `CloseIcon`; `MainChips` (a radiogroup of chips with roving tabindex: the chosen one is the only Tab stop, an arrow chooses the next).
- **`components/account/AccountTypesCard.js`** (new) — Account → Profile's **Your types** row (`id="types"`, `typesRow`: label, value, Change; greyed with `notReady` before 126) and the **Your types sheet** (the Switch board): portalled into `<body>` (outside the profile's `<form>`), a bottom sheet under 900px, a 480px dialog from 900px; `role="dialog"`, `aria-modal`, focus to the title (`tabIndex=-1`), Tab wraps inside, Escape / × / a press on the backdrop close and put the focus back on Change, `keepScrollInside` on the backdrop and the scrolling body. Rows from `sheetRows(draft, { isCreator })`: a checkbox per type (label + line), the `MAIN` pill or **Make main** (`canMakeMain`; `aria-describedby` the row's name), the creator note with its `/apply` link; `sheetNote` in the shield box; **Save** ("Saving…") → `POST` → close, update the row, announce `tapa:account-types`. Saves on its own, never with the profile's Save. A 503 `migration-126` shows `notReady`, anything else `failed`. Draft changes are dropped on close. `#types` opens it on arriving and on a hash change to it (`hashChangeComplete`, so the ☰ menu's "+ Add a type" works on the same page); closing drops `#types` from the address so that link opens it again. It listens for `tapa:account-types` too (the ☰ menu switching the main while this page is open).
- **`components/account/ProfileSection.js`** — takes `accountTypes` and draws `AccountTypesCard` at the top of the public card, under its head.
- **`pages/account/profile.js`** — reads `readAccountTypes(userId)` on the server (a failed read → greyed, as before 126) and passes it down with `isCreator`.
- **`pages/account.js`** — the hub reads `readAccountTypes` on the server and, when `askDue`, draws the **nudge** above the tiles: `askTitle`, `askSkipNote`, **Pick** → `/start?next=%2Faccount`, **Skip** → `POST { skip: true }` (announced) and the card goes (also on a 503 `migration-126`; any other failure says `failed`). The sign-in card: the Sign in button's `signUpForceRedirectUrl` and the Create account button's `forceRedirectUrl` are now `/signed-in?next=/account`.
- **`pages/welcome.js`** — the invitation's `<SignUp forceRedirectUrl>` and both sign-in buttons' `signUpForceRedirectUrl` are now `/signed-in?next=<next>` (`landing`).
- **`components/SiteMenu.js`** — the you card, under the name row: `menuTypes(state)` → the line (in the plan line's style, between the name row and the plan row), **Your main** and the chips as a radiogroup (`MainChips`; the main filled gold, others outlined), the dashed **+ Add a type** to `/account/profile#types` (closes the menu), the note. Choosing a chip shows at once and is saved 350 ms later (so arrowing through the chips sends only where it stops); a failed save puts the last saved main back and shows `failed`; a switch still waiting when the menu closes is sent at once. Signed out, or `accountTypes: null` (before 126): none of it. `lib/siteMenuRules.js` is unchanged.
- **`components/HeaderNav.js`** — passes `/api/my-role`'s `accountTypes` (signed in) to the menu and listens for `tapa:account-types` to update it.
- **`pages/profile/[userId].js`** — `typesLine(types, main)` under the name row (`.profile-types`), nothing for a watcher. The main column is now a list of `{ id, key, label, show, render }` ordered by `mainFirst(…, main, (s) => s.key)`, and both the jump list and the page map that one list, so the order is the DOM's: `profile-about` → `about`, `profile-crew` → `card`, `profile-record` → `record`, `profile-locations` → `places`, `profile-latest` / `profile-posts` → `posts`, `profile-tagged` → `work`, `profile-pitches` → `pitches`, `profile-saved` → `saved` and `profile-backed` → `backed` (keys no type leads with, so they keep their place among the rest). - **`styles/globals.css`** — one block, "Account types (2026-11-18, migration 126)", just before the No-zoom block at the end: `.atp-*` (the question, the row, the sheet), `.acct-types-nudge*`, the menu's `.sm-you-types` / `.sm-type-chip` / `.sm-type-add`, `.profile-types`. Tokens only (`var(--…)`, `rgba(var(--brass-rgb|--danger-rgb), a)`, `color-mix(… var(--ink) …)`); no literal hex. Text on orange and gold is `var(--surface-0)`. Touch screens get 44px chips.
- **`lib/adsenseRules.js`** — `/start` added to the private prefixes (no AdSense script on the question; it is an account page like `/welcome`).
- **`scripts/test-sign-in-here.mjs`** and **`dev/test-rig/checks/sign-in-here.mjs`** (section 6) — their expectations for the general ways in follow item 2 (a sign-up from the account card or the door now lands on `/signed-in`).
