# Taprino Productions — Studio Tapa TV

Indie OTT streaming platform (studiotapatv.site) for Studio Tapa / Studio Taprino content: films, series, podcasts, short-form vertical video ("Snippets"). Built and run solo by Jose under an LLC that also runs Studio Tapa (Shopify stickers/paper goods) and Post Puppeteers (client video production). Not launched publicly yet.

Differentiator: creators get funded by their audience — **Pitch Room** (donation-style funding, platform takes a cut) and a self-serve **advertiser system** with admin-reviewed ad creative.

Repo: https://github.com/josehernandezcasas2-sudo/Taprino-Productions (branch `main`, Vercel auto-deploys on push).

## Layout

- Web app (repo root): Next.js 14, **Pages Router**, plain JS. `pages/`, `components/`, `lib/` (data + helpers), `contexts/`, `styles/`, `middleware.js`.
- `supabase/migrations/NNN_name.sql`: numbered migrations, run **manually** in the Supabase SQL Editor (latest: 081). Never assume one is applied; features fail with "table not found" until it is.
- `mobile/`: Expo SDK 57 / React Native 0.86 app, Expo Router in `mobile/src/app/`, plain JS. Calls the web app's API via `mobile/src/lib/api.js` (add a new `pages/api/*` route when a screen needs data `getServerSideProps` currently provides). Bottom nav (`mobile/src/components/BottomNav.js`) mirrors `MobileTabBar.js`'s full site map (Home/Discover/Watch/Account groups) even where the destination screen is still a placeholder — check what's actually built before assuming a nav entry has real content behind it. Colors/spacing/radii live in `mobile/src/lib/theme.js`, pulled from `styles/globals.css`'s real `:root` values, not invented. A Figma file (https://www.figma.com/design/4bWVu8cjMI1otCAyvSxs5T) holds a matching design system (variables, Nav/Tab Bar components, reference pages) built from the same code — edits there get manually ported back into both codebases on request, there's no live sync. Real device testing is via Expo Go on Jose's iPhone; the Expo CLI on this PC and Expo Go must both be signed into the same Expo account ("studiotapa237") or opening the project fails.
- Live channels (`/live`, TapaTV is CH 01): the rules for what airs live in `lib/channelPlan.js` (pure, tested by `node scripts/test-channel-plan.mjs`); `lib/channelEngine.js` loads data and answers "what's on." Order: live broadcast > published week > default schedule > loop. Slots take whole minutes (a 27:40 title fills a 28-minute slot; the rest is ads), and gaps under 5 minutes play ads instead of the loop. Scheduler at `/schedule` (tablet/computer only; phones get a note): edits a draft of the whole week/default view and saves it in one go through `/api/schedule/save` (`saveDays` in `lib/scheduleAdmin.js`); drag/resize/ad-break/ripple rules in `lib/scheduleLayout.js` (pure, tested by `node scripts/test-schedule-layout.mjs`), drawn by `components/ScheduleTimeline.js` (one day: drag/resize, Shift-click multi-select, ripple) and `components/ScheduleWeekStrip.js` (the week at a glance, which doubles as the day tabs; bars drag between times and days). The channel's "ads between shows" gap (`channels.ad_gap_seconds`, migration 074) is where blocks snap to land after a show; the gap plays ads via the short-gap rule. Channels at `/admin/channels`, moderation (flags, reports, `moderation_hold`) in `lib/moderation.js` and `/admin/content`. Every public episode/series query filters `moderation_hold = false`; keep that in any new public query.
- Content ratings are data: `content_ratings` (migration 076) via `lib/ratings.js` (cached; falls back to the built-in list in `lib/contentRatings.js`), edited on `/admin/ratings` (custom ratings with their own minimum age, and the PNG bug per rating). `meetsAgeRequirement(age, rating, ratings)` takes that list; forms use `components/RatingOptions.js`. The channel player shows the bug top-left as a program starts, hides its controls while playing, and keeps between-program ad breaks at least 10 minutes apart. Live play gate (`/api/channel/play`): a viewer with an age on file gets the age check; anyone else (signed out, or no age set) watches rated programs after taking the live TV terms once (`/terms#live-tv`; remembered in localStorage / SecureStore and sent as `liveTerms`). The guide shows real loop items faded in the loop colours (`mergeForGuide` only merges loop slivers under `LOOP_ITEM_MIN_SECONDS`).
- Pitch Room Discover (`/pitches/discover`) is an elevator: each pitch is a floor, `components/PitchElevator.js` renders the cab/doors/buttons/flippable card, the page owns the ride state. Riding is a swipe on the card (left/right/up = next floor, right also likes, down = hold for a second-look round; tap either face to flip; no floor indicator); the right plate reacts (Save = `pitch_saves` follow, Share, Like = `pitch_likes`, migration 073). Web keyboard: ↑ next, ↓ back a floor, H hold, F flip, S save, L like. Ride progress is `/api/pitch-swipe-progress` (with `floorIndex`). The mobile app has the same elevator (`mobile/src/components/PitchElevator.js`, `mobile/src/app/pitches/discover.js`) fed by `/api/pitch-discover-feed`. Saved pitches show on `/wishlist` and the app's My List (`/api/wishlist-feed`).
- Crew Call (`/crew`, Connect → Crew Call; app: Discover → Crew Call, `mobile/src/app/crew/`): the network. Everyone with an account gets a **working card** (`/crew/card`, `crew_cards` + `crew_gear` + `crew_credits`, migration 079): roles from `lib/crewOptions.js`, gear with a brings/lends/ask flag (no money moves through the site), place + travel radius + remote, availability, optional day rate (signed-in viewers only), languages, outside credits (released titles are credits automatically). `lib/crewCards.js` owns reads/writes/validation and the directory search (`/api/crew/people`: role, gear category, distance from a point via `lib/geocode.js` (OpenStreetMap Nominatim, cached in `geocode_cache`), open/verified). lat/lng never leave the server; "✓ creator" is the Clerk creator role. Profile pages show the card (`crewCard` from `lib/profileHub.js`). Not built yet: the calls board + pitch "crew needed" block, location-based call notifications.
- Messages (`/messages`, `/messages/<threadId>`, `/messages?to=<userId>&kind=gear|card|profile|call&label=…`; app: `mobile/src/app/messages/`, Account → Messages): in-app DMs, migration 080 (`dm_threads` one per sorted pair, `dm_messages`, `dm_thread_state` read/mute/last-emailed, `user_blocks`, `dm_reports`). `lib/messages.js` owns it: anyone signed in can write (20 new conversations / 200 messages a day), block stops it both ways and hides the blocker's card from the blocked person's directory, mute = no email/badge; a report snapshots the last 20 messages into `dm_reports` (read on `/admin/messages`, cap `handle_flags`) and files a profile report. Recipient gets a `notifications` row (type `message`) and an email (Resend) at most once per thread per 30 min. `/api/notifications` carries `messagesUnread` for the header badge; the app polls it in `mobile/src/lib/useUnread.js`. New messages arrive by polling (10 s open thread, 30 s inbox), no websockets, no push. Client-safe constants live in `lib/messageRules.js` (lib/messages.js imports Clerk's server client and can't be bundled into a page).
- Film University (`/university`, Connect side; app: Home → Film University) is a free online university (v3, signed off 2026-10-10; the earlier "Workshop"/exercises shape is gone): departments → courses → modules → lessons, and everything lives under a course. Data in migrations 078 + 081: `uni_topics` (departments) → `uni_courses` (slug, level `start`/`2`/`3`, `needs`, `next_course_id`, cover) → `uni_modules` (headings) → `uni_lessons` (kind `video` = Cloudflare Stream manifest in `video_src`, signed on the way out like episodes; kind `document` = PDF "reading" in the public `university-docs` bucket; optional assignment title/text/minutes, text = brief, blank line, then steps one per line) and `uni_files` (per course or per lesson; `role` `material` = a download, `example` = something to look at, which gets its own Examples tab on the course and lesson pages; `kind` `file` (any type, `lib/universityDocs.js` FILE_TYPES, 50 MB) or `video`). `uni_progress(user_id, lesson_id)` syncs ticks for signed-in viewers: `lib/universityProgress.js` (`useProgress`, localStorage `uni_done_lessons`, merged into the account once via `/api/university/progress`); the app does the same with SecureStore (`mobile/src/lib/universityProgress.js`). `lib/university.js` does all reads/writes (`getUniversityFeed`, `getCoursePage`, `getLessonPage`, `getLibrary`, admin savers). Pages: `pages/university/index.js` (catalogue with Continue strip + Library shelf), `[course]/index.js` (Syllabus / Materials / Examples tabs), `[course]/[lesson].js` (Overview / Files / Examples / Assignment, "Mark done · next lesson"), `library.js` (every file, filter by type/department); the app's equivalents in `mobile/src/app/university/{index,course/[slug],lesson/[course]/[slug],library}.js` call `/api/university/{feed,course,lesson,library,progress,stream-token}`. Admin: `/admin/university` (`components/admin/UniversityEditor.js`, capability `manage_university`): departments → courses → modules/lessons → course files, up/down reorder, video via TUS upload (`/api/admin/university-upload-url` + `-video-status`), files straight to Storage via a signed upload URL (`/api/admin/university-document-upload-url`). Lesson and example videos play with `VideoPlayer`'s `refreshSrc` prop (no ads, no age/tier gate).
- Admin (`/admin`, redesigned 2026-10-08): every `pages/admin/*.js` page renders inside `components/AdminShell.js` (grouped left nav from `lib/adminNav.js`, filtered by capability, chip strip on phones) and gates with `adminPageProps(ctx, { caps })` from `lib/adminPage.js` (no caps = full admins only; sub-admins get in with any listed capability). The dashboard is numbers + the merged review queue (`lib/reviewQueue.js`, `/api/admin/review-queue`: submissions, ads, series, channel uploads; `components/admin/ReviewQueue.js`) + flags + recent activity; the old hub's sections are their own pages (`/admin/review`, `library`, `settings`, `pitch-room`, `ownership`, `audit-log`). `/admin/styles` (Styles & Guides) holds theme colors and every icon set; the old theme/genre-icons/player-icons/site-icons URLs redirect there. New admin page = add an entry to `ADMIN_NAV`, wrap in AdminShell, gate with adminPageProps. The mobile app shows an Admin tab to admins/sub-admins (`mobile/src/lib/adminRole.js`): `mobile/src/app/admin/index.js` (home) and `review.js` (card-by-card approve/reject; ads and series deep-link to the web).
- Root `*.md` files (HANDOFF, DEPLOY_NOTES, *-NOTES) are historical session notes. HANDOFF.md has the fullest product background but is partly dated.

## Stack

Clerk (auth; **live/production keys**, same account works across web and mobile — the mobile app calls web API routes with a Bearer token from `useAuth().getToken()`, which `getAuth(req)` on the server accepts the same way it reads a session cookie), Supabase Postgres (server-side only, service-role key), Cloudflare Stream (direct browser TUS uploads; playback is signed HLS via `/api/stream-token`, provider-agnostic by design so swapping in Bunny.net later needs no player changes), Stripe (subscription metadata only; **no real charges yet**), Upstash Redis (analytics), Resend (transactional email), Brevo (newsletter). Env vars: see `.env.local.example`.

## Commands

```bash
npm run dev              # web on :3000
npm run build            # web production build
cd mobile && npx expo start
cd mobile && npx expo install <pkg>   # never plain npm add in mobile
```

Mobile: Expo APIs change every SDK. Check `mobile/AGENTS.md` and the versioned docs (https://docs.expo.dev/versions/v57.0.0/) before writing Expo/RN code. Keep non-route code out of `mobile/src/app/`. Not built for real devices/stores yet — that's `eas build`/`eas submit` (EAS handles iOS/Android signing automatically), not needed until there's an app worth shipping.

## How Jose likes to work

- **Mockups and sign-off before building** anything with real visual/design decisions.
- One thing at a time: build, verify completely, then move on.
- Flag real bugs found along the way, even out of scope; call out scope creep explicitly.
- Be honest about built vs. not built. Don't assume something is done because it was discussed.
